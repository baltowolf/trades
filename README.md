# MOEX Stock Tracker v6 — sell-only

Трекер только для продаж. На входе — [`portfolio.json`](portfolio.json:1) с тикером,
количеством и ценой входа. На выходе — Telegram-уведомления, когда сетка тейков
или стоп говорят продавать.

Файлов `fundamentals.json` и `ideas.json` больше нет в проекте — они не нужны.
Сетка фиксированная, ATR для планирования больше не используется. ATR и RSI
остались только в дашборде как справочная информация.

## Вход

```json
{
  "SBER": {
    "count": 14,
    "buy_price": 285.99
  },
  "LKOH": {
    "count": 1,
    "buy_price": 6065.5
  },
  "CASH": 10448
}
```

- `count` — количество акций.
- `buy_price` — цена входа. От неё считаются и тейки, и стопы.
- `target` — необязательный и больше не влияет на сетку. Оставлен для обратной
  совместимости: скрипт хранит его в state, но уровни строит по фиксированной сетке.
- `stop` — необязательный ручной начальный стоп. Если он не задан или задан выше
  цены входа, используется стоп `-6%` от входа.
- `CASH` — свободные деньги, только для дашборда.

## Что приходит в Telegram

- **СТОП** — цена упала до стопа или ниже; продать всю позицию.
- **TP1 / TP2 / TP3** — частичная фиксация или полное закрытие.
- **ГОРИЗОНТ** — прошло 180 дней с начала плана; продать всю позицию.

В каждом сообщении: цена, цена входа, P&L, точное количество акций и лотов,
чистый результат после комиссии и НДФЛ, остаток и новый стоп с процентом от входа.

## Формулы

### Точка отсчёта

```text
entry = buy_price (цена входа)
```

Все проценты в сетке и стопах считаются от `entry`, а не от текущей цены.
`plan_anchor` в state равен цене входа. `avg_cost` используется для P&L,
налога и безубытка.

### Сетка тейков

| Ступень | Условие | Доля продажи | Что делает стоп по остатку |
|---|---|---|---|
| Старт | покупка | 0% | `-6%` от входа (или ручной `stop`) |
| TP1 | `+7%` | 30% позиции | `+0.5%` от входа — безубыток |
| TP2 | `+14%` | 30% позиции | `+8%` от входа |
| TP3 | `+22%` | весь остаток (40%) | позиция закрывается |

Доли указаны в процентах от исходной позиции. Из-за округления до лотов
фактические доли могут немного отличаться; последняя ступень всегда продаёт
весь остаток.

Если цена гэпом проходит несколько уровней сразу, скрипт продаёт суммарную
долю достигнутых ступеней. Если цена уже выше TP3 на момент старта плана,
позиция закрывается полностью.

### Стопы

- До TP1 (пока пик ниже `+7%`): стоп остаётся на `-6%` от входа. Это даёт
  запас на обычный рыночный откат голубых фишек в 3–5% и не выбивает позицию
  на шуме.
- После TP1: стоп не ниже `+0.5%` от входа. Этого хватает на комиссию и НДФЛ,
  поэтому риск убытка по сделке обнуляется.
- После TP2: стоп не ниже `+8%` от входа и дополнительно трейлит по формуле
  `peak - 5%`, но никогда не опускается ниже `+8%`. К цели `+22%` трейлинг
  даёт примерно `+16%` от входа.
- `stop_current` после достижения тейков только повышается, никогда не понижается.
- Стоп-триггер считается по `min(last, bid)` — по цене, по которой реально
  можно продать.

### Горизонт

Через 180 дней с начала плана (3–6 месяцев под среднесрочные идеи) — продать
всю позицию. Это защита от «зависших» позиций.

### Старые ATR-планы

При первом запуске v6 старые планы из `state.json` автоматически переводятся
на процентную сетку от `buy_price`. Прогресс продаж (`sold`, `realized_pnl`,
`opened_at`) сохраняется. Если по позиции уже была зафиксирована прибыль,
её стоп не понижается. Если продаж ещё не было и цена не дошла до `+7%`,
старый узкий стоп расширяется до `-6%`, чтобы не выбивало шумом.

## Команды

| Команда | Назначение |
|---|---|
| `python moex_tracker.py` | основной цикл |
| `python moex_tracker.py --once` | одна диагностическая итерация |
| `python moex_tracker.py --show` | последние уведомления |
| `python moex_tracker.py --send-pending` | дослать неотправленное в Telegram |
| `python moex_tracker.py --stats` | статистика закрытых сделок |
| `python moex_tracker.py --migrate` | backup и сброс state |
| `python moex_tracker.py --reset-plan TICKER` | пересчитать план от цены входа |
| `python test_fixes.py` | самотесты |

## Запуск

```bash
pip install requests
cp .env.example .env
# заполните TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID

python test_fixes.py
python moex_tracker.py --once
python moex_tracker.py
```

`--once` полезен для первой проверки: он покажет дашборд, текущие планы и все
сигналы. Если Telegram не настроен, сообщения печатаются в консоль.

## После продажи

Скрипт не выставляет заявки. После исполнения обновите [`portfolio.json`](portfolio.json:1):

- частичная продажа — уменьшите `count`;
- полная продажа — удалите тикер или поставьте `count: 0`.

Если этого не сделать, скрипт считает, что рекомендация ещё не исполнена, и не будет
спамить повторными сообщениями по той же ступени. Для ручного пересчёта используйте
`--reset-plan TICKER`.

## Что удалено

- Файлы `fundamentals.json` и `ideas.json` удалены из проекта.
- Скринер, входной движок, Kelly, корреляционные кластеры и прочая сложность.
- Ядро и спутник — все акции продаются по общим правилам.
- ATR-ладдер и target-ладдер заменены фиксированной сеткой `+7 / +14 / +22%`.

## Ограничения

- Скрипт не выставляет заявки и не гарантирует прибыль.
- Сетка фиксированная и не подстраивается под волатильность конкретной бумаги.
- Дивиденды и налоговый вычет по убыткам не моделируются.
- Проскальзывание не учитывается в отчётном P&L (только комиссия и НДФЛ).
- `target` больше не проверяется и не влияет на уровни.

## Дисклеймер

Это инструмент расчёта и уведомлений, а не инвестиционная рекомендация.
Решение об исполнении принимает владелец капитала.
