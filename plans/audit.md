# Аудит moex_tracker.py — план исправлений

## A. Баги и корректность кода

### A1. Версия в docstring не совпадает с header
- [`moex_tracker.py`](moex_tracker.py:2): docstring говорит **v3.5**
- [`print_header()`](moex_tracker.py:1476): выводит **v3.6**
- **Фикс:** синхронизировать версию

### A2. RSI считается через SMA, не через Wilder's EMA
- [`_rsi()`](moex_tracker.py:467): использует `sum(gains[-period:]) / period` — это SMA-based RSI
- Классический RSI (Wilder) использует экспоненциальное сглаживание: `avg_gain = (prev_avg_gain * (period-1) + current_gain) / period`
- SMA-RSI даёт другие значения, особенно при коротких историях. Пороги `BUY_RSI_THRESHOLD = 32` и `GOLD_RSI_ENTRY = 38` калиброваны под какой именно вариант?
- **Фикс:** заменить на Wilder's smoothing, пересмотреть пороги

### A3. Peak сбрасывается при рестарте скрипта
- [`init_position()`](moex_tracker.py:637): `"peak": max(buy, stock["last"])`
- Если скрипт перезапускается, peak = max(buy_price, текущая цена). Если акция была на 300₽, а сейчас 290₽ — peak = 290₽, хотя реальный пик был 300₽.
- Chandelier stop (peak − 3 ATR) будет занижен → стоп ближе к цене → ложный стоп
- **Фикс:** при инициализации брать `highest_high` из свечных данных за `TRAILING_LOOKBACK_DAYS`

### A4. Telegram-токен захардкожен в исходнике
- [`TELEGRAM_BOT_TOKEN`](moex_tracker.py:46): реальный токен в коде
- Если репо публичное — бот скомпрометирован
- **Фикс:** убрать дефолтное значение, оставить только `os.environ.get("TELEGRAM_BOT_TOKEN", "")`

### A5. `notification_exists()` — O(n) чтение файла при каждом вызове
- [`notification_exists()`](moex_tracker.py:200): загружает весь JSON с диска
- [`dispatch_notification()`](moex_tracker.py:207) вызывает её, потом опять `load_notifications()`
- Два полных чтения файла на каждое уведомление
- **Фикс:** передавать уже загруженный список, или кешировать в памяти

## B. Торговый алгоритм

### B1. TP1 при 1.5 ATR vs стоп 2.5 ATR = отрицательный Risk/Reward на первом тейке
- Риск: 2.5 ATR вниз. Reward TP1: 1.5 ATR вверх = **0.6R**
- Первая фиксация (25% спутника) происходит при R:R < 1.0
- Для тренд-следящих систем это снижает математическое ожидание
- **Рекомендация:** поднять TP1 до 2.0–2.5 ATR (минимум 1R), либо уменьшить initial_stop до 1.5 ATR

### B2. Стоп 2.5 ATR — тесноват для MOEX
- Стандартный Chandelier Exit: 3.0 ATR. Российский рынок волатильный — 2.5 ATR может давать частые ложные стопы
- При ATR% 2-4% для ликвидных бумаг, 2.5 ATR = 5-10% просадка — в целом нормально
- **Рекомендация:** протестировать 3.0 ATR initial stop, сравнить hit rate

### B3. Сигнал на покупку — дневной дроп 3% + Z < -1.5 + RSI < 32
- Три фильтра одновременно — **очень** консервативно, сигналы будут редкими
- На бычьем рынке может месяцами не давать входов
- `trend_up` (> EMA50) правильно фильтрует контртрендовые покупки
- **Рекомендация:** ослабить один из фильтров. Например RSI < 38 или Z < -1.2

### B4. Пирамидинг блокирован если цена ниже средней покупки
- [`run_iteration()`](moex_tracker.py:1447): `if st["last"] <= pos["buy_price"]: continue`
- Если упало на 5% и дало сигнал — докупка не произойдёт, хотя это именно момент для усреднения
- **Вопрос:** это осознанное решение "не усредняться вниз"? Если да — ОК. Если нет — убрать проверку

## C. Риск-менеджмент

### C1. Нет лимита совокупного риска портфеля (portfolio heat)
- Каждая позиция рискует 1.5% капитала, но если 10 позиций одновременно на стопе — потеря 15% капитала за день
- **Рекомендация:** добавить `MAX_TOTAL_RISK_PCT = 6.0` — не открывать новые позиции если суммарный risk > порога

### C2. Нет учёта корреляции секторов
- 5 из 15 позиций — нефтегаз (LKOH, GAZP, TATN, ROSN, SNGSP). Падение нефти = все 5 на стопе одновременно
- 3 из 15 — банки (SBER, VTBR, T). Ставка ЦБ вверх = все 3 страдают
- **Рекомендация:** добавить `MAX_SECTOR_POSITIONS = 3` или `MAX_SECTOR_PCT = 30%`

### C3. Нет circuit breaker при большой просадке
- Если портфель просел > 10% за день — скрипт продолжает работать как обычно
- **Рекомендация:** добавить `MAX_DAILY_DRAWDOWN_PCT = 5.0` — при превышении стоп на все новые покупки до конца дня

### C4. Cash = 287₽ — нулевой запас
- Нет сухого пороха для новых покупок. Любой сигнал на покупку бесполезен
- Это не баг скрипта, но портфельная проблема
